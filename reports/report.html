Документация содержит критические архитектурные и логические дефекты, включая передачу чувствительных данных в query-параметрах GET-запросов, несоответствие типов данных между API и требованиями, отсутствие описания краевых условий для периодов и диапазонов, а также внутренние противоречия в спецификации контракта API.

Исправить в первую очередь
  1. Исправить метод API для сохранения настроек с GET на POST/PUT/PATCH и перенести параметры из query в тело запроса для исключения передачи cardId в логах.
  2. Устранить противоречия в контракте API, исправив HTTP-методы, статусы (200 OK вместо Created) и типы данных поля amount между запросом и ответом.
  3. Дописать правила конвертации величин (тиыны и тенге) при сравнении расходов с порогом.
  4. Описать поведение системы на границах периодов, часовые пояса и правила сброса счетчиков.
  5. Конкретизировать диапазоны валидации, структуру ошибок и обязательные параметры в исходных условиях.

В функциональном требовании Ф-2 указано: «Переводы и снятие наличных исключаются». Исправить: Заменить действие в критерии с перевода на покупку или явно указать, что перевод проигнорирован системой в соответствии с Ф-2.

Исправить: Измените тип запроса в дочерней спецификации с GET на POST (или PUT), а также скорректируйте пример вызова через curl.
