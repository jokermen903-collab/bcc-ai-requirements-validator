Разработку начинать: нет. Тестирование: нет.

Документ содержит критичные архитектурные и функциональные дефекты: использование HTTP-метода GET для изменения состояния системы, передачу чувствительных данных в query-параметрах, отсутствие URL для промышленного контура, а также многочисленные противоречия в типах данных API и кодах ответов. Разработка и тестирование по текущей версии невозможны, так как это приведет к уязвимостям безопасности и несогласованности реализации.

Исправить в первую очередь
  1. Для метода сохранения (изменения) настроек используется HTTP-метод GET, который по стандарту HTTP является безопасным и идемпотентным методом для чтения данных, а не для изменения состояния системы.
  2. Для метода сохранения порога используется REST type GET, при этом чувствительные параметры (cardId, amount, enabled) передаются в query-параметрах. Это приводит к тому, что идентификатор карты и настройки попадают в URL, логи веб-серверов и историю браузера.
  3. Для промышленного контура (Prod) не указан URL метода, что делает невозможным развертывание и интеграцию сервиса в боевой среде.
  4. Описание метода содержит внутреннее противоречие: название и первая часть говорят о сохранении порога, а вторая часть отсылает к чтению порога.
  5. В спецификации ответа тип поля amount указан как string, в то время как в query-параметрах запроса и модели данных это число (integer).
