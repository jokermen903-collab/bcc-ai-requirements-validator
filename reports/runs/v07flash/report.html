Документация содержит критические дефекты и противоречия, препятствующие разработке и тестированию. Обнаружены несоответствия HTTP-методов семантике (GET для изменения данных), противоречия в передаче тела запроса и Content-Type, рассинхронизация единиц измерения (тенге и тиыны), а также логические дыры в сценариях мультивалютных операций и изменения порогов. Отсутствуют схемы отката и необходимые методы API.

Исправить в первую очередь
  1. Устранить противоречие в контракте API между использованием HTTP-метода GET и операцией сохранения настроек (изменения данных)
  2. Исправить несоответствие кода ответа 200 и заголовка Created, приведя их в соответствие с семантикой REST
  3. Устранить противоречие между утверждением, что тело запроса не используется, и передачей параметров через query/data строку при наличии заголовка Content-Type: application/json
  4. Привести к единой системе измерения денежные величины (тенге и тиыны) для корректного сравнения порога и суммы расходов
  5. Добавить недостающий метод API для чтения настроек и устранить путаницу в описании метода /alerts/saveLimit
  6. Определить правила конвертации и суммирования расходов для операций в иностранной валюте
  7. Описать бизнес-логику для сценария изменения порога в середине периода (поведение при уже накопленной сумме)
  8. Заполнить пустые заглушки в требованиях к тестированию конкретными правилами и сценариями
  9. Добавить схему отката решений и использование feature toggle
  10. Указать Prod-адрес в поле Request URL и описать статус-код 404 в перечне ответов API
